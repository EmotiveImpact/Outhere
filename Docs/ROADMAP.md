# OutHere Roadmap

The app's screens and navigation are largely built, but much of what they show is hardcoded, there are no real accounts, and the backend trusts whatever the phone sends. This roadmap replaces what sits underneath the screens, one phase per pull request, without redesigning them.

Each phase starts only once the previous phase's "done when" check passes.

## Phase 0: Clean foundation (done)

- One app: `apps/mobile`. The old Emergent `frontend/` app and generated root clutter are removed.
- The Anything (create.xyz) runtime is gone: no fetch override, launcher menu, remote error reporting or sandbox messaging.
- Step sync posts the real count (it used to post 0 every 30 seconds) and uses the local calendar day.
- The DEV BYPASS button only exists in development builds; a failed signup no longer onboards a local-only account.
- The committed Mapbox token is removed; route planning falls back to OSRM without one.
- App identity: name `OutHere`, scheme `outhere`, bundle ID `com.outhere.app`, real permission strings. Native projects are generated by `expo prebuild` / EAS instead of committed.
- iOS maps use Apple Maps (Google Maps needs an SDK and key we don't ship).
- The backend installs from `requirements.txt` and its smoke tests live in `backend/tests`.

**Done when:** the app bundles for iOS, Android and web with only OutHere's own config.

## Phase 0.5: The whole app working on the phone (done)

The server decision is parked so the product can be built and felt first.

- `src/data/engine.js` owns all data in AsyncStorage, simulates a seeded world of 24 players and 5 crews, and applies the rules for XP, OUT, streaks, battles, crews, events, drops, rewards and memberships.
- Every screen reads through React Query hooks (`src/data/hooks.js`) and is built from one design kit (`src/components/ui`). All mock arrays, fake fallbacks, `/api/*` fetches and dead buttons are gone.
- Membership limits are enforced and open an upgrade sheet. Payments are not live, so switching plan is free in this build.
- The old `services/api.js` client and the unused Mapbox and RevenueCat packages are removed, so the app runs in Expo Go.

**Done when:** every tab and detail screen works end to end offline. A server later replaces `engine.js` behind the same functions.

## Phase 1: Accounts and real data

- A dedicated Supabase project: real tables, Row Level Security, Storage for crew logos.
- Sign in with Apple, Google or an email code. The random `device_id` is retired.
- Step ingest goes through a server function that rejects future dates, caps backdating at one day and caps daily steps.
- `src/services/api.js` moves onto Supabase.

**Done when:** two test users cannot read or change each other's data.

## Phase 2: Core loop for real

- Home, Move, Crew and Arena on live data; runs saved to the server.
- Battles and the XP/OUT ledger become database functions with unique keys (no double payouts), and battles complete on a schedule.
- Crew chat and feed in realtime. Every mock array and fake fallback is removed, with proper empty and error states.

**Done when:** none of the five main tabs shows hardcoded data.

## Phase 3: Memberships and payments

- RevenueCat in-app purchases for Pro and Black, with a 14-day Pro trial.
- A store webhook sets the membership tier; gating is enforced on the server.
- Black application and invite flow behind the 14-day streak.

**Done when:** a sandbox purchase unlocks Pro end to end.

## Phase 4: Events, drops, rewards and social

- Events and drops run from a simple admin, with RSVP capacity enforced.
- Rewards catalogue and OUT redemption with weekly limits.
- Friends, user search, news feed and push notifications.

**Done when:** spec tasks 001 to 008 in `Docs/Task` all pass their checks.

## Phase 5: Launch readiness

- Apple Health and Google Fit, background step tracking.
- Crash reporting, analytics, anti-cheat caps and rate limits.
- EAS builds, TestFlight beta, store listings and a privacy policy.

**Done when:** a TestFlight beta is live with real users in London.
